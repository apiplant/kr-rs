# Resolved

## Control plane (ADR-021)
107. **Networking gaps (conformance round 7)** — *fixed*
    Fixed:
    - `kr server` and `kr agent` raise `RLIMIT_NOFILE` to the hard limit. At the default soft limit of 1024 `accept` failed with EMFILE once enough Services were listening, which is the likely cause of the `10.96.0.1 i/o timeout` / TLS handshake timeouts seen across the suite (not reproduced in the e2e run itself).
    - The service proxy indexes Endpoints and EndpointSlices, uses slices (falling back to Endpoints), yields while reconciling, and backs off when reconciling is slow.
    - The `kubernetes` Service gets an EndpointSlice.
    - The EndpointSlice mirroring controller.
    - `services/[scheme:]name[:port]/proxy`; proxy URLs are parsed by segment (namespaces named `proxy-*` broke it); `https` targets (certificate not verified, as upstream; the TLS client's insecure mode is an explicit separate constructor); HTML links rewritten through the proxy.
    - hostNetwork pods and `status.hostIP`: fixed in #108.
    - DNS for musl clients, checked live with upstream's probe commands (`dig +search` over UDP and TCP, `getent hosts`, PTR) from the Alpine-based agnhost image: services, headless services, `hostname.subdomain` records, pod A records and PTR all resolve, with NODATA (not NXDOMAIN) for AAAA of existing names. Fixed: ExternalName answers now include the records of in-cluster targets after the CNAME, as CoreDNS does (musl does not re-query a CNAME; chains followed up to 8 hops, loops end); `/etc/hosts` lists `<hostname>.<subdomain>.<ns>.svc.cluster.local` for pods with a subdomain, as upstream's kubelet (`hostname -f`, getent).

110. **CRD conversion webhooks** — *fixed*
    Webhook CRDs were never converted. Now:
    - **Writes:** POST/PUT/PATCH in any served version are stored in the storage version. The order is authorization, then (PATCH) the stored object converted to the request version, then admission webhooks in the request version, then a dry-run in the request version for errors and field validation, then conversion and the write at the storage version's URL; replies are converted back. Strategy None re-routes synchronously.
    - **Reads:** objects and lists are converted per stored version, one ConversionReview each, validated like upstream (uid, Success, count, apiVersion, kind, metadata unchanged, compared key-order-insensitively: Go webhooks re-serialize with sorted keys).
    - **Watches:** events are converted in the stream (one in-flight batch, non-blocking); a failure ends the watch with an ERROR event (500).
    - Verified: `tests/conversion.rs` (HTTPS webhook in-process: storage form, dry-run, legacy objects, watch, failure) and live with upstream's `agnhost crd-conversion-webhook` and the e2e CRD (create/get/list/patch/watch across v1 and v2, server dry-run, strict validation, namespace deletion).
111. **kubectl describe panic and log filters** — *fixed*
    kubectl's `describe service` dereferenced EndpointSlice port names that kr omitted for unnamed ports (now always `name: ""`). `kubectl logs --since/--since-time` were ignored and `--timestamps` used the file's mtime; the kubelet now samples each log file's size every 500 ms, giving per-line times accurate to ~0.5 s for filters and timestamps. Not reproducible on a live cluster (left open): Update Demo, Guestbook and the attach-denial message all worked; their round-7 failures were likely load/connectivity. Noticed: `get -o wide` lacks wide columns; fresh pods show no events in `describe`.

## Node agent and controllers (phase 4)
71. **No probes** — *fixed*
    exec, tcpSocket and httpGet as startup, liveness and readiness probes, with upstream thresholds. Network probes run inside the pod network namespace (they work rootless). HTTPS httpGet probes are treated as TCP probes.
72. **No `kubectl logs/exec/attach/port-forward`** — *fixed*
    - logs (`--tail`, `-f`), exec (WebSocket v4/v5, stdin, exit codes) and attach work.
    - port-forward works over SPDY/3.1, both tunneled in WebSocket and as a direct upgrade, verified with kubectl 1.37.
    - Port-forward does not enforce SPDY flow control, because kubectl ignores it; backpressure comes from the transport instead.
74. **Rootless pods have no pod IP** — *fixed*
    An infra user+net namespace holds the bridge, and pod sandboxes are nested in it. Pods get IPs and reach each other (verified).
75. **Resource requests are not enforced** — *fixed*
    CPU requests become `cpu.weight` (upstream formula); memory requests become `memory.min` (Guaranteed) or `memory.low` (Burstable), skipped silently when the memory controller is not delegated; `status.qosClass` is computed as upstream. Every pod gets a cgroup `kr-pods/<uid>` (Guaranteed), `kr-pods/burstable/<uid>` or `kr-pods/besteffort/<uid>` with the summed container limits (memory/cpu/pids only when every container sets one; init containers count as their peak, `spec.overhead` is added), holding the sandbox in a `pause` leaf and the container cgroups below; it is removed with the pod. Memory-pressure eviction: every 10 s, if MemAvailable is below the threshold (default 100Mi, `KR_EVICTION_MEMORY_AVAILABLE` overrides), the node condition `MemoryPressure` is True, the node gets the `node.kubernetes.io/memory-pressure:NoSchedule` taint (removed when pressure clears; the scheduler already filters NoSchedule taints) and one pod is evicted per tick: BestEffort first, then Burstable/Guaranteed pods whose pod-cgroup `memory.current` exceeds their summed requests (largest excess first). Evicted pods get phase Failed, reason `Evicted`, and are not restarted; `system-*-critical` and static pods are never evicted. Verified live on two docker nodes (cgroup tree, Guaranteed `memory.max` 64Mi, BestEffort evicted and Guaranteed spared). Not done: soft thresholds, disk/pid eviction, pod priority ordering, minimum-reclaim, ephemeral containers added later count against the pod limit, and without a delegated cgroup there is no usage data (only BestEffort pods are evictable).
76. **Controllers are basic** — *fixed*
    Deployment (pause, progress deadline, minReadySeconds), StatefulSet, DaemonSet, Job (with pod failure backoff), CronJob, Endpoints/EndpointSlice and the namespace controller exist.
77. **Image pulls block the kubelet sync loop** — *fixed*
    Pulls run as background tasks; failures back off and are reported as `ImagePullBackOff`.
94. **Graceful pod deletion never completes** — *fixed*
    Found in conformance round 3: pods that got a `deletionTimestamp` before the kubelet ever admitted them (tests create + delete faster than the sync loop) stayed `Terminating` forever — `terminate()` returned early when the pod was not in the kubelet's runtime map, so the API object was never removed (49 marker pods stuck on one node for 45+ min; pods with client-set finalizers lingering is upstream-correct behaviour, a different case).
    Fix: the kubelet force-deletes (`gracePeriodSeconds=0`) terminating pods it has no runtime state for, matching upstream `kubelet.deletePod`. Verified live: three create+delete races all removed within one sync cycle.
    Not covered: apiserver-side eviction of pods on a dead node (upstream uses the taint manager; kr has no node-lifecycle controller yet).
95. **Sonobuoy aggregator gets `Unauthorized` from kr's apiserver** — *fixed*
    Found in conformance round 3: about an hour after pod start, every request from a pod's service account returned 401 (sonobuoy spammed `unable to list pods ... Unauthorized` every few seconds, the aggregator never discovered the e2e job pods, and sonobuoy never completed), so the run stayed `running` in the API even though the suite had finished and written its log — `conformance.sh wait` hangs on this.
    Cause: the kubelet's projected-volume refresh decided a mounted token was fresh by file mtime, and every 20 s republish rewrote the file — so an expired token was republished forever.
    Fix: `spec.rs` `stage_volume` reads the token's own `iat`/`exp` claims (`token_lifetime`) and renews at 80% of the real lifetime. Verified live: a pod with `expirationSeconds: 600` rotated its token exactly at 480 s, and the rotated token authenticated (403 on a forbidden list, not 401).

## Services, DNS, multi-node (phase 5, ADR-022)
81. **No Node authorizer** — *fixed* (ADR-023)
    Nodes read only the secrets/configmaps/PVCs of their own pods and write only their own Node, Lease and pods. Pods themselves remain readable cluster-wide (as upstream). Token requests are checked by service account, not by `boundObjectRef`.
82. **Bootstrap token never expires** — *fixed* (ADR-023)
    `kr token create --ttl 24h` mints expiring join tokens; the server's initial `node-token` stays permanent (k3s-style), so delete its Secret (`kube-system/bootstrap-token-<id>`) to retire it. Agents rotate their client and serving certificates at 2/3 of their lifetime and hot-swap them, with no restart.
86. **Defaulting is a subset** — *fixed*
    Defaults cover core/apps/batch plus networking (NetworkPolicy), storage (StorageClass, CSIDriver), PV/PVC phase, Endpoints/EndpointSlice ports, PriorityClass, RBAC binding subjects, admissionregistration webhooks and ValidatingAdmissionPolicy, and flowcontrol.
89. **Agent join token visible in the process list** — *fixed* (commit: b37c07d)
    `kr agent --token VALUE` exposed the token in /proc/<pid>/cmdline. Use `--token-file` (must be mode 600) or `KR_TOKEN`; `--token` still works but warns.
90. **Pod sandbox holder costs ~0.6–0.9 MB PSS per pod** — *fixed* (commits: 8f76327, bfd9d3e)
    After setup the holder execveats kr (O_PATH|O_CLOEXEC fd of /proc/self/exe) as `kr pause` with an empty environment and all other fds closed: ~77 kB PSS per pod instead of ~700 kB. If the exec fails it silently falls back to the old in-process pause.
93. **Containers survive a killed kr as orphans** — *fixed* (with #75)
    On startup the kubelet kills every process left in the `kr-pods` cgroup tree (`cgroup.kill`, or SIGKILL per pid on older kernels), waits for it to empty and removes the cgroups, before pod sync. Containers started before pod cgroups existed, and rootless/undelegated setups (no cgroups), are not covered.

## Runtime (kr-rt)
1. **Pending task + Async forms an Rc cycle** — *fixed* (commit: 68940ad)
   The task owns the future, the future owns the `Async`, the `Async`'s I/O slot owns a waker, and the waker owns the task. A task that never completes is never freed.
   Plan: add `JoinHandle::abort()` to drop the future and break the cycle, and add a live-task counter for leak detection. Rule: every network wait must have a deadline.
   Fix: `JoinHandle::abort()` drops the future immediately, and the handle then resolves to `Err(Aborted)` (the output is now `Result<T, Aborted>`, and there is also `is_finished()`). `exec::live_tasks()` counts tasks until their `Task` is freed, and `kr sleep-test` asserts on it (`live_tasks_ok`). A task that never completes and has no deadline or abort is still a leak hazard by design.
2. **`sleep` can fire up to 1 ms early** — *fixed* (commit: 68940ad)
   The millisecond clock is truncated. Plan: round deadlines up, so a sleep never fires before it was asked to.
   Fix: deadlines are computed in ns (`now_ns`), `Sleep` completes only when `now_ns >= deadline`, and the wheel entry uses `ceil(deadline_ns / 1e6)`. `kr sleep-test` verifies every elapsed time is >= the requested one.
4. **Allocator never returns small blocks to the OS** — *fixed (e64a857)*
   RSS grows to peak usage and stays there. Fine for the agent, but it could matter for a long-running server. Fix: 64 KiB-aligned per-class chunks with live counts; an emptied non-current chunk is madvised (header page kept) and reused, with no re-mmap.
6. **Large allocations with alignment above 4096 are not honoured** — *fixed (e64a857)*
   They go through mmap, which only guarantees page alignment. Fix: over-allocate with mmap and munmap the head/tail so the pointer has the requested alignment.
10. **mem\* are byte-by-byte on non-x86_64, and memcmp/bcmp everywhere** — *fixed (e64a857)*
    Fix: word-at-a-time memcpy/memmove/memset (non-x86_64) and memcmp/bcmp, volatile stores keep them from becoming self-calls; exhaustive tests.

## Worked through 2026-11-12 (uncommitted)
143. **API priority and fairness: no work estimation, no borrowing** — *fixed*
    A request now takes `width` seats: 1 for everything except a LIST of a collection, which takes one seat per 100 stored objects (counted in the requested namespace or the whole kind, bounded by `limit=`), at most 10, and never more than the level's limit. A queued wide request waits at the head of its flow queue until its seats are free. Priority levels borrow: `lendablePercent` of a level's limit may be used by other levels while idle, a level may hold at most `borrowingLimitPercent` of its limit on top of its own (unset: unlimited), and borrowed seats return as the borrowing requests finish (every release also wakes queued requests of the other levels). The total of 600 seats is configurable with `KR_APF_SEATS` (read once, a positive number; invalid or 0 means 600). Tests: width tiers, seat env parsing, borrowing, limits and giving back.

135. **CSI: no `volumesInUse` accounting** — *fixed*

138. **Device plugins: no `GetPreferredAllocation`, no topology hints** — *fixed* (ADR-038)
    A plugin that registers with (or reports in `GetDevicePluginOptions`) `get_preferred_allocation_available` is asked, per container, which N of the free healthy devices to hand out; the answer is used if every id is free and the count matches, else the default choice applies. Without plugin preference the `topology.nodes` hint of `ListAndWatch` is used: the devices come from one NUMA node if some node has enough free ones (the node with the fewest free devices that still fits, to keep big nodes whole), else the first free ones. Unit tests use a fake plugin.

139. **Device plugins: a device turning unhealthy does not fail or evict its pod** — *fixed* (ADR-038)
    `Plugins::unhealthy_holders` lists (pod uid, container, resource, devices) holding a device that a live `ListAndWatch` reports Unhealthy or no longer lists; `unhealthy_pods` turns that into one message per pod. The kubelet's 10 s eviction loop marks such pods like a memory eviction (phase `Failed`, reason `Evicted`, message `container X uses R device D reported unhealthy by its device plugin`) and kills them. A plugin that is merely gone (restart, upgrade: the stream ended) does NOT fail pods: its devices are unknown, not broken, so a GPU Operator upgrade does not kill every GPU pod.

233. **Per-key precomputed tables for CA keys (verification)** — *fixed* (was #219)

234. **TLS tickets died with the process and did not work across HA servers** — *fixed* (#209, #220)
    `TicketKeys::set_secret` (`resume.rs`) derives the ticket key of each hour as `HKDF(secret, "kr tls ticket key v1" || hour)` (key id from the same derivation); a ticket opens in the hour it was sealed and the hours either side, so clock skew of up to an hour between servers is tolerated. `kr server` passes `HKDF(sa.key, "kr tls ticket secret v1")` (`sa.key` is identical on every server of a cluster and never used directly as a ticket key) to `kr_net::tls::set_ticket_secret` before it accepts connections, so a restart keeps every ticket and a client may resume against any server. The ticket still carries the config binding (server certificate, client-auth mode and roots): servers with different certificates do not accept each other's tickets. The trust assumption is the same as for `sa.key` itself (whoever has it can already mint service-account tokens), but a leaked `sa.key` now also lets an attacker forge tickets that carry a client certificate chain, i.e. any identity; rotating `sa.key` invalidates all tickets. Tests: `shared_secret_keys_open_across_instances_and_restarts`, `tickets_survive_a_restart_and_work_across_servers_with_a_shared_secret`.

Tests: `stats::tests::volume_stats_are_rendered_...`, `tools/test/volume-stats.sh` on a rootless server (a pod writing 3 MB into a local-path claim, the metrics and the summary).

269. **`node.status.volumesAttached` was not written; the unmount wait lived in memory** — *fixed* (was #135)
    The attach/detach controller publishes `status.volumesAttached` (`kubernetes.io/csi/<driver>^<handle>`, `devicePath: ""`) for every VolumeAttachment whose `status.attached` is true, until the attachment is gone, patching only nodes whose list changed (so `kubectl describe node` shows attached volumes and a client can wait on it as with upstream). The time an unwanted attachment has been waiting for the node to unmount it is stamped on the attachment (`kr.io/unwanted-since`, wall-clock seconds) the first time a run sees it, so a restarted or newly elected controller continues the 6 minute maximum instead of starting over. Tests: `attachdetach::tests::attached_volumes_are_published_on_the_node`, `the_unmount_wait_survives_a_restart`.

270. **`seccompProfile` was ignored** — *fixed* (part of #131, ADR-055)
    Containers honour `securityContext.seccompProfile`: `RuntimeDefault` and no profile run the default filter, `Unconfined` runs without one, `Localhost` compiles an OCI/Docker profile file from the kubelet's seccomp directory (actions, caps/arch conditions, argument conditions; see ADR-055); a bad or missing profile is a `CreateContainerConfigError`. Exec'd processes get the same filter. The default filter refuses syscalls newer than the build's table with ENOSYS. Tests: `seccomp::tests` (5), `tools/test/seccomp.sh` (7 checks against real containers).

271. **Each image was unpacked in full: shared base layers were duplicated** — *fixed for root* (part of #130, ADR-056)
    A root kr stores each layer once under `layers/` (overlay whiteouts and opaque markers) and mounts an image's layers as a multi-`lowerdir` overlay; a layer another image already holds is not unpacked or stored again. Falls back to the flattened rootfs when a layer cannot be represented. Tests: `tools/test/layers.sh`, and an alpine image installed layered and run from its layer directory in a user namespace. Not run on your cluster yet (needs a rebuild; images pulled afterwards are layered).

272. **The device-plugin checkpoint was fsynced on the event loop** — *fixed* (part of #215)
    `persist` writes the file atomically without fsync and flushes it with `offload::fsync_file` in a worker, so an Allocate no longer waits for the disk.

273. **A CSR's `status.certificate` was not validated** — *fixed* (part of #206)
    The `status` update needs an approved, not denied/failed request, an unchanged-once-set value, a parsable PEM chain, and a first certificate whose public key equals the request's.

274. **A kubelet could list every VolumeAttachment and PersistentVolume** — *fixed* (part of #207)
    List/watch of `volumeattachments` requires `fieldSelector=spec.nodeName=<node>` (or one own name); `persistentvolumes` lists/watches are denied unless limited to one name the node uses.

275. **The kubelet's start-up sweep ran as one uninterrupted poll** — *fixed* (part of #215)
    `sweep_unclaimed` is async and yields between its steps and after every removed pod/container directory.

276. **A kubelet restart ends exec and attach sessions** — *closed as upstream parity* (#134)
    The client's TLS/WebSocket connection ends in the kubelet process, so no design lets a session survive that process short of handing the socket and TLS state to another process. Upstream's kubelet does not either: it proxies the runtime's streaming server (`proxyStream`), so restarting it drops `kubectl exec`/`attach`/`port-forward` there too. Containers, their terminals and `attach -i` stdin do survive in kr (the shim keeps them). The shim costs ~1 MB per container, far below containerd-shim-runc-v2.

277. **Images and layers were never removed** — *fixed* (part of #130, ADR-057)
    The kubelet checks every 5 minutes; above `KR_IMAGE_GC_HIGH` (85 %) of the store's filesystem it removes images no pod on the node names and no container directory records, least recently used first, never younger than `KR_IMAGE_GC_MIN_AGE` (120 s), until usage is at or below `KR_IMAGE_GC_LOW` (80 %). Removing an image drops its refs, directory, the shared layers and the blobs no remaining image uses. `tests/gc.rs` covers sharing.

278. **NetworkPolicy chains had one rule per peer pod IP and port** — *fixed* (part of #202)
    `netpol_batch` puts three or more single-address peers with the same ports into a named hash set (`<chain>-s<n>`, elements in messages of 512) and matches it with one `lookup` rule per port; checked in a real kernel (`tools/test/nft-proxy.sh`, scenario `pol-set`) and by `peers_with_the_same_ports_become_a_set`.

279. **A pod whose sandbox could not be built failed for good** — *fixed*
    Any `start_sandbox` error other than "no free IP" (a full disk writing `/etc/hosts`, a CNI error, a vanished file) set `failed_setup`, so the pod stayed `Failed` (`SandboxFailed`) and a ReplicaSet kept creating replacements. The kubelet now keeps the pod in `ContainerCreating`, emits one `FailedCreatePodSandBox` event per distinct message and retries every 10 s, as upstream. A container that cannot join a sandbox that has vanished (ESRCH) makes the kubelet drop the sandbox and build a new one.

280. **ServiceLB ignored ExternalIPs and served clashing ports twice** — *fixed* (part of #174)
    A node with `ExternalIP` addresses is published by those (else its InternalIPs), and of two LoadBalancer Services with the same protocol and port only the older (creation time, then namespace/name) gets an ingress.

281. **Audit and PodSecurity configuration are read at start-up only** — *closed as upstream parity* (#186)
    Upstream's kube-apiserver reads `--audit-policy-file` and the admission configuration at start-up too (and so does k3s); kr behaves the same, so a change needs a server restart.

282. **Load-balancer addresses were not served in userspace mode and `loadBalancerSourceRanges` was ignored** — *fixed* (part of #174)
    The userspace proxy now listens on a Service's `externalIPs` and its `status.loadBalancer.ingress` addresses at the Service port (before, only the node port was served, so the published ServiceLB address did not answer), and both datapaths enforce `spec.loadBalancerSourceRanges` on the load-balancer addresses: userspace drops connections and datagrams from outside the ranges at accept; nftables jumps to a per-address chain that returns for local sources and listed ranges and drops the rest (`Svc.limits`). Checked against a real kernel (`tools/test/nft-proxy.sh`, scenarios `lb-ranges`, `lb-ranges-prefix`) and by a unit test of the range match.

283. **No VolumeSnapshot support** — *closed as k3s parity* (#153)
    k3s's packaged components are coredns, traefik, local-storage, metrics-server and servicelb (docs.k3s.io, packaged components); it ships no snapshot controller or VolumeSnapshot CRDs either, so an external snapshotter is installed as a normal workload in both. (ADR-045.)

284. **The kubelet does not request serving certificates; no ClusterTrustBundles** — *closed as k3s parity* (#173)
    k3s passes the kubelet its serving certificate and key from the agent configuration (`ServingKubeletCert`/`ServingKubeletKey` in `pkg/daemons/agent/agent.go`, no `serverTLSBootstrap`), so its kubelet creates no CSRs either. `ClusterTrustBundle` is beta and off by default in Kubernetes 1.33 to 1.36 (stable only from 1.37, per the feature-gates page), so k3s does not enable it by default. CSR garbage collection and the `system:masters` subject check are done (RESOLVED 256, 273).

285. **The secrets-encryption key sits next to the data (no KMS or envelope key)** — *closed as k3s parity* (#190)
    k3s writes its encryption config to `<data dir>/cred/encryption-config.json` with a random AES-CBC or secretbox key and an identity fallback, and configures no KMS provider (`pkg/daemons/control/deps/deps.go`). Protect the data dir and any `kr snapshot` archive as credentials.

286. **Decrypted Secrets live in memory** — *closed as parity* (#191)
    kube-apiserver, which k3s embeds unchanged, keeps decoded objects in its watch cache; kr does the same. Memory dumps expose them in both.

287. **A driver upgrade does not reach running pods** — *closed as parity* (#163)
    Device libraries are bind-mounted when a container is created, as the OCI runtime and CDI do under containerd in k3s: a running container keeps the files it started with, and the pod must be restarted to see a new driver. Not testable here (no way to upgrade a driver under a running pod), so this rests on the mount semantics, not on a run.

288. **Certificate rotation needs a restart** — *closed as k3s parity* (part of #177)
    `k3s certificate rotate` also requires stopping the service first (docs.k3s.io, certificate). What k3s does better, an overlap period for the service-account key, stays open in #177.

289. **Only secrets are encrypted, and the list is edited by hand** — *closed as k3s parity* (part of #193)
    k3s generates an encryption config whose only resource is `secrets` and has no command for the list; kr offers more. The hazard of removing a resource that still holds ciphertext remains in #193.

290. **HPA custom and external metrics need an adapter** — *closed as k3s parity* (part of #196)
    k3s packages metrics-server only, so `custom.metrics.k8s.io` and `external.metrics.k8s.io` need a separately installed adapter there too. `status.krHistory` stays open in #196.

304. **`registries.yaml` `configs` had no `*` default; a removed encrypted resource looked unreadable** — *fixed / not a bug* (#175, #193)
    A `*` key under `configs` is now the credentials and TLS default for every registry without its own entry (the `*` mirror existed; k3s supports both). For #193 the documented hazard does not exist: the encryption codec decides by the stored value's `k8s:enc:` prefix, not by the resource list, so ciphertext of a resource later removed from `encryption-config.json` still decrypts as long as its key is present (`a_resource_removed_from_the_list_still_reads_back`); the codec is only absent when the config file is gone, which is the `disable` flow.

305. **NetworkPolicy did not filter traffic to the node itself** — *fixed for egress* (part of #201)
    The policy table has an `input` base chain beside `forward`: replies, ND, and Service addresses stay open, and a pod with an egress policy is judged by the same chain for packets addressed to the node. Real-kernel check: pod A with an egress policy reaches pod B but not the node's own address.

306. **Rotating the service-account key invalidated every token** — *fixed for one server* (part of #177)
    The signer can hold verify-only keys: `kr pki rotate --service-account-key` appends the old `sa.key` to `pki/sa-old.pem` (0600, part of `kr snapshot`), the server loads it, tokens signed by an old key verify (the header `kid` picks the key) and the JWKS publishes all keys. New tokens use the new key. Unit test `tokens_of_an_earlier_key_verify_while_it_is_kept`; end to end `tools/test/sa-rotate.sh`.

307. **Mirror path prefixes, `{n,m}` in rewrite, and no retry of blobs on the next endpoint** — *fixed* (part of #175)
    `endpoint` accepts `https://host/v2/<prefix>` (prefix prepended to the repository); the rewrite regex supports `{n}`, `{n,}`, `{n,m}` (counts up to 1000); `pull` splits into resolve and `finish`, so a mirror whose blobs fail hands over to the next endpoint and then the upstream.

308. **No zstd: `.tar.zst` archives and zstd layers were refused** — *fixed* (part of #176)
    `kr-archive::zstd::ZstdDecoder` (RFC 8878: Huffman and FSE literals and sequences, repeat offsets, skippable frames, concatenated frames, windows up to 128 MiB; no dictionaries, checksum not verified) streams like the gzip decoder, at about 190 MB/s of output in release. Layers and archives are recognised by their magic, so `+zstd` media types, `.tar.zst` files and mislabelled gzip/zstd layers work in `unpack`, `import` and `pull`. Tested byte for byte against the `zstd` binary at levels 1 to 22, with `--long`, empty and incompressible input, 1-byte and 4 KiB chunking, concatenated frames, and 300 randomly damaged streams (no panic); `tests/import.rs` imports a `.tar.zst` archive and an archive with a zstd layer.

309. **Re-encrypting stored Secrets needed the server stopped** — *fixed for `reencrypt`* (part of #188)
    `kr secrets-encrypt reencrypt --online [--server URL]` lists each configured built-in resource through the API with the admin certificate and writes every object back with `?krReencrypt=true`, which makes the server write although nothing changed (only for `system:masters`; a no-op update is otherwise skipped, as upstream). Checked by `tools/test/encrypt.sh`: after a key rotation and restart, every stored secret uses the newest key and still reads back.

310. **The cluster CA could not be rotated** — *fixed for one server* (part of #156)
    `kr pki rotate --ca prepare|activate|finish [--yes]` (`rotate.rs`): `prepare` creates the new CA (`ca-next.*`) and writes the bundle old+new to `ca.pem`; `activate` keeps the old CA as `ca-old.*`, writes the bundle new+old with the new key as `ca.key`, updates the hash in `node-token` and re-issues the leaf certificates and the admin kubeconfig; `finish --yes` leaves only the new CA in `ca.pem` and moves the old files aside. The server and agents already trust every certificate in `ca.pem`. Test: `tools/test/ca-rotate.sh`.

311. **Key changes of secrets encryption needed a restart** — *fixed* (part of #188)
    `POST /kr/encryption/reload` (system:masters) makes the server re-read `encryption-config.json` and swap the store's codec; `kr secrets-encrypt reload`, `rotate-key --online` and `disable --online` use it with `reencrypt --online`, which now also rewrites custom resources (storage version and scope from the CRD). `tools/test/encrypt.sh` rotates and disables a running server and checks the log and the readback.

312. **Service-account key rotation in HA** — *fixed* (part of #177)
    `kr pki rotate --service-account-key` is allowed in HA and prints the copy-then-restart procedure; `sa-old.pem` is part of the join files so a new server verifies old tokens.

313. **`registries.yaml` base paths and regex** — *fixed* (part of #175)
    Endpoint paths other than `/v2/<prefix>` set the base path the registry client puts in front of `/v2/`; `rewrite` supports lazy quantifiers, `(?:)`, `(?=)`, `(?!)` and replaces every match.

314. **Agents had to be given the new CA by hand** — *fixed* (part of #156)
    `GET /kr/ca-bundle` (public like `/cacerts`) returns the bundle in use; the agent's `track_ca` task fetches it every minute, writes `pki/ca.pem` when it differs, swaps the roots of its API client (`Remote::set_roots`) and reloads its kubelet API's client trust. Not run against a real agent.

315. **Air-gap import details** — *fixed* (part of #176)
    An agent started with `--data DIR` imports `DIR/images` too; an OCI archive whose index has no image for the node's platform is an error (`an_archive_without_this_platform_is_reported`), and a partial miss is reported on stderr.

316. **Operators fought the server over defaulted fields (20 writes a second, stalls of 1 to 2 s)** — *fixed*
    `update_ex` computed the generation (`prepare_update`) before it applied the defaults, so a PUT that left out defaulted fields (`strategy`, `dnsPolicy`, `terminationGracePeriodSeconds`, ...) looked like a spec change: the generation moved, the object was written, and the next writer saw a new resourceVersion. The tigera operator's whisker, goldmane and apiserver controllers did that to each other in a loop (the `calico-apiserver` Deployment was at generation 802,000 and the event loop stalled for 1.4 to 2.4 s on the large CRD and Deployment PUTs). Defaults are now applied first, so such a PUT is a no-op as upstream. `tests/update_defaults.rs`.

317. **ServiceLB re-evaluated every Service on every event** — *fixed* (#174, ADR-042)
    The watches now feed a `Tracker` that turns events into queue keys: a Service event enqueues that Service (plus the Services sharing one of its ports, whose clash outcome may change), an EndpointSlice event enqueues its owning Service, and a Node event enqueues "all" only when the node's Ready state or published addresses changed (heartbeats enqueue nothing). A key reconciles one Service (`sync_one`; EndpointSlices read per namespace); the periodic resync still does a full pass. Tests: `tracker_*` in `servicelb.rs`.

318. **A new pod was open for up to ~0.5 s (NetworkPolicy)** — *fixed* (#203, ADR-049)
    The pod's chain needed its IP, which reached the API only with the first status report. Now the kubelet, after it allocates the address and before any container starts (end of sandbox setup, built-in bridge only), registers it in the policy controller (`netpol::Ctl::announce`) and runs a pass (`Ctl::sync`), which overlays the announced IPs onto pods the API shows without any. The overlay entry is dropped once the API has the IPs. Test: `announced_ips_stand_in_until_the_api_has_them`; the kernel side is the existing nft tests. Not run on a live cluster here (no root).

319. **The kernel Service datapath is the default for root (part of #133)** — *fixed, verified in namespaces*
    `proxy::want_nft_mode`: unset `KR_PROXY` means nftables for root with kr's own network and no external CNI; `userspace` opts out. The bridge policy table (#205) got kernel tests in `tools/test/nft-proxy.sh`. What was not verified on a real cluster is listed under #133.

320. **Keys were copied by hand between HA servers** — *fixed* (part of #189, #156, #177, #188)
    A sealed key-sync record in the Raft log carries the CA files, `sa.key`/`sa-old.pem`, the tokens and the encryption config; every server applies it (atomic writes, live reload of encryption, SA signer and node-certificate CA) and acknowledges it (ADR-058). `kr pki rotate --ca` works in HA, `--service-account-key` and `secrets-encrypt rotate-key --online` replicate in two steps (read everywhere, then write), and the leader refuses a new write key until all voters can read it. `secrets-encrypt status` shows the cluster. Unit tests in `cluster/keysync.rs` (seal/open, tamper, ordering rule) and `encrypt.rs`.
321. **`kubectl get endpoints` had no ENDPOINTS column** — *fixed*
    Table conversion for `Endpoints` (printers.rs) prints upstream's `formatEndpoints`: up to three `ip:port` entries (IPv6 bracketed), then ` + N more...`, `<none>` without subsets.

322. **CSR approval validation was approximate** — *fixed* (#206, ADR-042)
    `kube-apiserver-client` CSRs naming `system:masters` or a group bound to `cluster-admin` can only be approved by a `system:masters` member; violations are field errors (`CertificateSigningRequest.certificates.k8s.io "n" is invalid: status.conditions: ...`); a `status.certificate` chain must start with an end-entity certificate and each issuer must be the next subject; apply requests go through the same `update_ex` check, and applying to `approval`/`status` of a missing CSR is 404 instead of creating it.

323. **Pod Security version pinning was partial** — *fixed* (#185, ADR-029, ADR-046)
    Version-gated rules added: baseline sysctl list (1.22/1.27/1.29/1.33 additions), AppArmor fields (1.30), `container_engine_t` SELinux type (1.31), Windows pods exempt from the restricted allowPrivilegeEscalation/capabilities/seccomp checks (1.25). `exemptions.usernames` reuses the request's authentication (no second token check). RuntimeClass exemptions match `spec.runtimeClassName` after RuntimeClass admission (Kubernetes has no default RuntimeClass, so there is nothing else to default).

324. **Audit parity: streams, in-process writers, PSA annotations, identity** — *fixed* (#180, #181, #182, #184; part of #183, ADR-046)
    `Audit-ID` header, single authentication per audited request (the audit hook hands the pre-impersonation identity to the handler), `ResponseComplete` when a watch/log stream ends, in-process controller/kubelet writes audited as their `system:kr:<component>` user, Pod Security `audit-violations`/`enforce-policy` annotations recorded by admission (after the decision, also denied requests and updates), `--audit-log-format legacy`, `--audit-log-maxage`.

325. **Images: manual removal (#130)** — *fixed*
    `kr ctr rmi <image|id>...` (reference, id or 12+ hex prefix) and `kr ctr rmi --prune`; both refuse images a container directory records (`images_in_use`), and `--prune` also sweeps blobs no manifest names older than an hour (`Store::sweep_blobs`). `kr ctr run` records its image; a record-less container directory older than the boot no longer stalls the garbage collector (ADR-057). 327. **Kubelet `/metrics/cadvisor`, `/metrics`, `/metrics/probes`** — *fixed* (part of #199, ADR-048)

328. **CSI offline expansion, retries and `NodeResizeError` (part of #136)** — *fixed* (ADR-041)
    `Csi::expand_if_needed` runs `NodeExpandVolume` (a) on mount: `mount_pv` expands a claim whose request exceeds `status.capacity` (and fits the PV) after stage/publish, before the container starts, so a claim that grew while no pod used it is expanded on its next use; (b) for running pods in `expand_pending` once the resizer set `FileSystemResizePending`; (c) for raw block claims without that condition. A failure sets the claim condition `NodeResizeError` (reason `NodeExpandFailed`), emits a `VolumeResizeFailed` Warning event on the claim, and retries with exponential backoff (2 s doubling to ~2 min; the pod waits in ContainerCreating at mount); success clears the condition, sets `status.capacity` and emits `VolumeResizeSuccessful`. Block expansion sends the `block` capability. Tests: `offline_expansion_on_mount_then_failures_back_off_with_a_resize_error_condition`, `raw_block_volume_is_staged_published_as_a_device_expanded_and_unlinked`, `expands_volume_once_the_resizer_is_done`. 364. **Kubelet image credential provider plugins** — *fixed* (ADR-069)
    `image-credential-provider-config` (a `CredentialProviderConfig`, YAML or JSON) and `image-credential-provider-bin-dir` work as in the upstream kubelet. For a pull whose image matches a provider's `matchImages` (upstream URLsMatch: per-label wildcards, port, path prefix) kr runs `<bin dir>/<name>` with the configured args and env, writes a `CredentialProviderRequest` to its stdin and uses the longest matching `auth` key of the `CredentialProviderResponse`, alongside pull secrets and `registries.yaml` (pull secrets win on equal specificity). Results are cached per `cacheKeyType` until `cacheDuration`, else the provider's `defaultCacheDuration`, else 5 minutes. The plugin runs asynchronously with a 60 s timeout; a failing plugin is logged and the pull goes on without it. Tests: matching, parsing, cache, and an exec of a script plugin. Not done: `[...]` classes in globs; plugin binaries are not ownership-checked as hooks are.

365. **`kr token` list, delete, generate, rotate** — *fixed* (ADR-070)
    `list` (bootstrap-token Secrets with id, TTL or expiry, usages, description; the server's join token marked), `delete ID...`, `generate` (prints a random token, stores nothing), `rotate [--new-token T]` (new Secret first, then `node-token` rewritten and replicated through key sync in HA, then the old Secret deleted; same CA hash required). A running server picks up the new file within ~2 s (`keysync::watch_pki`). New joins need the new token; joined agents use their node certificates and are unaffected. Checked live (rootless): generate, create, list, rotate, list, delete. The HA `server-token` (admits servers, seals key-sync records) is not rotated by this command.

362. **OIDC and webhook authentication/authorization, optional admission plugins** — *fixed* (ADR-071)

363. **Kubelet resource managers and graceful node shutdown** — *fixed* (ADR-072; live run pending, verification backlog)
    CPU manager `static` (`cpu-manager-policy`, `reserved-cpus`, `full-pcpus-only`): integer-CPU containers of Guaranteed pods get exclusive CPUs (cgroup v2 `cpuset.cpus`), everyone else the shared pool, running containers rewritten on change; topology from sysfs, choice by whole sockets, cores, then threads; `cpu_manager_state` checkpoint (upstream layout) so adopted containers keep their CPUs. Memory manager `Static` (`reserved-memory`) pins memory to NUMA nodes via `cpuset.mems`. Topology manager `none`/`best-effort`/`restricted`/`single-numa-node` (container scope) merging hints from the CPU, memory and device-plugin managers; refusals are `TopologyAffinityError`/`SMTAlignmentError` as upstream. Graceful shutdown (`shutdown-grace-period`, `-critical-pods`, `-by-pod-priority`): a logind delay inhibitor through kr's own small D-Bus client; on `PrepareForShutdown` the node goes NotReady, new pods are refused, pods stop group by group and end Failed/`Terminated` with the upstream message and a `DisruptionTarget` condition; a cancelled shutdown restores Ready; a too-low `InhibitDelayMaxSec` is raised through a logind drop-in. 21 unit tests (sysfs fixtures, allocation, hint merging, checkpoints, D-Bus encoding, shutdown groups). Not done: devices are aligned at container start rather than admission; multi-NUMA memory groups; `reserved-memory` does not lower allocatable; little-endian D-Bus only; no cpuset controller rootless.
